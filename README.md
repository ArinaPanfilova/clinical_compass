# Компас — цифровой ассистент врача (прототип)

Система поддержки решений для ведения взрослых пациентов с тревожной и депрессивной
симптоматикой. Два кабинета (врач и пациент), стандартизированные шкалы, динамика,
проверка применимости препарата, алертинг и маршрутизация. **Все клинические действия
выполняет только врач.** Все данные синтетические.

![Кабинет пациента](docs/screenshots/patient.png)

## Состав

```
kompas_core/        ядро клинической логики (роль 2), чистый Python + PyYAML
  scales/*.yaml     паспорта шкал PHQ-9, GAD-7: расчёт, пропуски, пороги, источники
  rules/*.yaml      правила алертинга и маршрутизации (черновики до утверждения)
  drugs/*.yaml      карточка Авиандра (по вторичному источнику — сверить с ГРЛС)
  scales.py         подсчёт с явной политикой пропусков
  dynamics.py       MCID, надёжное изменение (RCI), ответ, ремиссия, тренд
  rules_engine.py   движок правил с трёхзначной логикой (да / нет / неизвестно)
  drugs.py          проверка показаний, противопоказаний, взаимодействий
  text_screen.py    вспомогательный поиск тревожных фраз в дневнике
  pipeline.py       evaluate_patient(record) → JSON для API
synthetic/          генератор пациентов с независимым эталоном + демо-сценарии
evaluation/         оценка алертинга: чувствительность, специфичность, PPV с ДИ
analysis/           скрипты для открытых датасетов (психометрика, динамика)
api_stub/           эталонный FastAPI без БД — для демо и как образец бэкенду
frontend/           интерфейс врача и пациента (роль 4), React + TypeScript + Vite
tests/              58 тестов ядра
docs/METHODOLOGY.md решения, источники, ограничения, вопросы клиническому лиду
docs/API_CONTRACT.md формат данных для бэкенда
```

## Запуск

```bash
pip install pyyaml pytest fastapi uvicorn pandas scipy
python -m pytest                                  # тесты ядра
python evaluation/evaluate_alerts.py              # метрики → evaluation/results/
python synthetic/demo_patients.py                 # демо-данные для фронтенда

uvicorn api_stub.main:app --port 8000             # сервер правил (терминал 1)
cd frontend && npm install && npm run dev          # интерфейс (терминал 2) → http://localhost:5173
```

Без сервера интерфейс открывается на демо-данных, но правила не пересчитываются:
клиническая логика живёт только на сервере и во фронтенде не дублируется.

## Сценарий для записи экрана (≈ 90 секунд)

1. Кабинет врача: триаж-список, у Марии С. экстренный сигнал — показать жизненный цикл алерта, «Основание» с источниками.
2. Анна К.: Авиандр «можно рассмотреть»; Игорь В.: «недостаточно данных»; Сергей М.: «не подходит» (противопоказание).
3. Переключиться на «Пациент» → Анна заполняет анкету, на вопрос 9 отвечает «Более половины дней» → отправляет.
4. Вернуться к врачу: у Анны срочный алерт «Обязательно: психиатр» → «Принять в работу» → «Подтвердить» → запись в журнале.
5. Кнопка «Мне сейчас очень плохо» у пациента: экстренная инструкция показывается сразу.

## Анализ открытых датасетов

```bash
python analysis/psychometrics.py data/mendeley.csv --out analysis/results/mendeley
python analysis/monitoring.py data/kaggle.csv --id <колонка id> --time <колонка дня> --score <сумма PHQ-9>
```

До запуска прочитайте раздел 7 в `docs/METHODOLOGY.md`: описание датасета Mendeley на сайте
не совпадает с описанием организаторов.
