# Доработка «Компаса» до требований ТЗ — дизайн

Дата: 26.10.2026. Ветка: `agent/claude/tz-completion`. Срок заморозки кода: 27.10, 14:00 МСК.

## Цель

Закрыть обязательные условия и функции ТЗ, которых нет в прототипе, и добавить отличительную
функцию — аналитику применения Авиандра. Ядро `kompas_core` (шкалы, правила, проверка препарата)
не переписываем: его контракт `evaluate_patient(record)` остаётся прежним.

Что уже есть и не меняется: паспорта PHQ-9/GAD-7, YAML-правила алертинга и маршрутизации,
проверка Авиандра с трёхзначной логикой, генератор синтетики и оценка алертинга, UI кабинетов.

## Решения

| Вопрос | Решение |
|---|---|
| Кто пишет код | Только мы, ветка в репо ArinaPanfilova/clinical_compass |
| Роли | Врач, Пациент, Исследователь |
| Бэкенд | FastAPI + SQLite (stdlib `sqlite3`, WAL), развитие `api_stub` в `server/` |
| Аналитика | Врач — по своим курсам; Исследователь — вся когорта обезличенно, группы n < 5 скрыты |
| Данные аналитики | Те же таблицы, что заполняют врач и пациент (курсы, анкеты, отметки приёма, НЯ) |

## Блок 1. Сервер `server/`

### Хранение

SQLite, `journal_mode=WAL`, `synchronous=FULL`, `foreign_keys=ON`. Схема — `server/schema.sql`.
Таблицы:

* `users` — логин, хэш пароля (`hashlib.pbkdf2_hmac`), роль `doctor|patient|researcher`, имя,
  `patient_id` для роли пациента.
* `patients` — демография, `primary_scale`, диагнозы, профиль безопасности, чек-лист симптомов,
  контекст (JSON-поля), `emergency_active`, `selfreports_missed_consecutive`, сценарий.
  **«Неизвестно» хранится как NULL/отсутствие ключа, не как false.**
* `care_links` — пациент, лечащий врач, заместитель, `active`.
* `assessments`, `diary`, `adverse_events` (с `severity mild|moderate|severe` и `serious`).
* `therapy_courses` — препарат, МНН, показание (МКБ-10), начало, конец, `stop_reason`
  (`completed|adverse_event|inefficacy|improvement|switch|lost_to_followup`), назначивший врач.
* `intake_marks` — дата, `taken|missed`, причина пропуска.
* `messages` — пациент, отправитель, текст, `created_at`, `delivered_at`, `read_at`.
* `decisions` — решения врача по находкам (как в заглушке + `doctor_id`).
* `alerts` — `saved_at`, `created_at`, `delivered_at`, `accepted_at`, `accepted_by`, `closed_at`,
  `status`, `assigned_to`, `escalation_level`.
* `self_reports` — ключ идемпотентности и сохранённый ответ.
* `audit_log` — кто, какая роль, действие, пациент, время, разрешено ли.

`server/records.py::build_record(conn, pid)` собирает запись в формате `docs/API_CONTRACT.md`.
`weeks_on_current` считается от начала активного курса.

### Роли и доступ

* Вход: `POST /auth/login` → подписанный токен `user_id.exp.hmac` (stdlib `hmac`), заголовок
  `Authorization: Bearer`. Для SSE токен передаётся параметром `?token=` (EventSource не умеет
  заголовки).
* Политика `can_view_patient(user, pid)`:
  * пациент — только свой `patient_id`;
  * врач — пациенты с активной связью, где он лечащий; заместитель — только пациенты, у которых
    есть незакрытый алерт, эскалированный на него;
  * исследователь — никогда; ему доступен только `/analytics/*`.
* Каждое обращение к карточке и каждый отказ пишутся в `audit_log`.

### Эндпоинты

| Метод | Путь | Кто |
|---|---|---|
| POST | `/auth/login`; GET `/me` | все |
| GET | `/patients`, `/patients/{id}` | врач (свои); пациент — только `/patients/{свой}` |
| POST | `/patients/{id}/self-report` (заголовок `Idempotency-Key`) | пациент (свой) |
| POST | `/patients/{id}/intake` | пациент (свой) |
| GET/POST | `/patients/{id}/messages`; POST `/messages/{id}/read` | пациент (свой), врач (свои) |
| POST | `/patients/{id}/decisions` | врач |
| GET | `/alerts`; POST `/alerts/{id}/ack`, `/accept`, `/close` | врач (назначенные ему) |
| GET | `/events/stream?token=` (SSE) | врач |
| GET | `/analytics/aviandr?…фильтры` | врач (свои курсы), исследователь (все, обезличенно) |
| POST | `/demo/reset` — только при `KOMPAS_DEMO=1` | все |
| GET | `/health` | все |

Сервер раздаёт собранный фронтенд (`frontend/dist`), поэтому запуск — одна команда
`python -m server`. Dockerfile — тонкая обёртка над ней.

### Алерт-конвейер

1. Самоотчёт пациента: в **одной транзакции** записываются данные, вычисляется
   `evaluate_patient`, создаются строки `alerts` (статус `created`), сохраняется ключ
   идемпотентности. Потом commit.
2. Повтор с тем же `Idempotency-Key` возвращает сохранённый ответ, данные и алерты не дублируются.
   Открытый алерт по тому же пациенту и правилу не создаётся повторно.
3. После commit алерт публикуется подключённым SSE-клиентам назначенного врача. Клиент
   подтверждает получение (`/ack` → `delivered_at`). При подключении клиент получает все свои
   недоставленные алерты — так переживается разрыв связи и перезапуск сервера.
4. Фоновая задача раз в секунду: алерт `emergency|urgent`, не принятый за
   `KOMPAS_ESCALATE_AFTER_S` (демо — 60 с), переназначается заместителю (`escalation_level+1`,
   повторная публикация). Доступ заместителя открывается только к этому пациенту.
5. Экстренная инструкция пациенту показывается на клиенте сразу, не дожидаясь сервера (как сейчас).

## Блок 2. Аналитика Авиандра

### Синтетическая когорта `synthetic/aviandr_cohort.py`

Около 300 курсов, фиксированный seed, 6 врачей; у демо-врача около 40 курсов. Завершённые курсы —
пациенты с неактивной связью: в списке пациентов их нет, в аналитике есть.

* Показания: F41.1 и F43.2 с пост-COVID контекстом; возраст 18–75; пол; коморбидности
  (сердечно-сосудистые, эндокринные, нет); сопутствующая терапия (антидепрессант, нет).
* Визиты каждые 2 недели, план 8–12 недель, GAD-7 и PHQ-9. Исходный GAD-7 10–21, индивидуальная
  скорость снижения, шум.
* Отметки приёма с индивидуальной приверженностью; часть дней — неизвестно.
* НЯ с тяжестью; список терминов берётся из раздела нежелательных реакций инструкции
  (вторичный источник до сверки с ГРЛС).
* Отмены с причинами. Все параметры — допущения генератора, на экране пометка «синтетические данные».

### Ядро аналитики `kompas_core/analytics.py` (чистые функции)

Вход — список курсов (словарь: курс, обезличенный ключ пациента, врач, возраст, пол, показание,
коморбидности, сопутствующая терапия, даты, `stop_reason`, визиты по неделям, счётчики приёма, НЯ).

* `filter_courses(courses, f)` — период начала, возрастная группа, пол, показание,
  коморбидность, сопутствующая терапия, врач.
* `kpis` — назначено; продолжают; завершили; отменили всего и по причинам.
* `trajectories(scale, by="outcome_group")` — по неделям 0, 2, …, 12: медиана, Q1, Q3, n.
  Группы: «продолжил/завершил», «отменён из-за НЯ», «отменён из-за неэффективности», «другое».
* `response_rates(scale)` — ответ (снижение ≥ 50 %), клинически значимое улучшение (≥ MCID из
  паспорта шкалы), ремиссия (< 5) на последнем наблюдении; числитель и знаменатель.
* `adherence` — доля подтверждённых приёмов среди известных; доля неизвестных отдельно;
  группы ≥ 80 %, 50–79 %, < 50 %.
* `safety` — НЯ по терминам и тяжести, доля курсов с НЯ, серьёзные НЯ, отмены из-за НЯ.
* `benefit_index(scale)` — **индекс устойчивой пользы** = курсы с ответом на последнем
  наблюдении, без серьёзных НЯ и без отмены из-за НЯ / все начатые курсы с исходным измерением
  (ITT; потерянные из наблюдения = без пользы). 95 % ДИ Вильсона, компоненты рядом.
* `suppress_small(…, k=5)` — для исследователя ячейки и точки с n < 5 заменяются на «скрыто».

Оговорка на экране и в API: «Наблюдение без контрольной группы. Изменение шкалы не отделяет
эффект препарата от естественного течения и регрессии к среднему».

### Экран «Авиандр»

Фильтры сверху; ряд KPI; график медианы GAD-7 (PHQ-9 переключателем) с полосой Q1–Q3 по группам;
причины отмен; распределение приверженности; таблица НЯ по тяжести; плитка индекса с формулой и ДИ.
Графики — SVG, как существующий `TrendChart`, без новых зависимостей.

## Блок 3. Остальное

1. Сообщения врач↔пациент: вкладка у пациента подключается к API; у врача — блок «Сообщения»
   в карточке. Новое сообщение приходит врачу через тот же SSE. Статусы видны обеим сторонам.
2. Отметка приёма у пациента на экране «Сегодня»: «Принял / Пропустил» + причина без
   обвиняющих формулировок. У врача — доля подтверждённых приёмов и доля неизвестных.
3. Экран входа с кнопками демо-аккаунтов: врач, заместитель, пациенты сценариев, исследователь.
   Без сервера фронтенд, как сейчас, открывает демо-данные без входа (только кабинеты).
4. Метрики → `evaluation/results/`:
   * `load_test.py` — 100 виртуальных сессий (80 пациентов / 20 врачей) с паузами; p50/p95/p99 по
     эндпоинтам, доля ошибок;
   * `alert_latency.py` — сохранение → создание алерта → доставка по SSE, 200 прогонов;
   * `recovery_test.py` — `kill -9` сервера во время потока самоотчётов, перезапуск; сверка:
     подтверждённые отчёты на месте, алерты не потеряны и не задвоены; время восстановления;
   * матрица доступа роль × эндпоинт × свой/чужой пациент — pytest, цель 0 несанкционированных.
5. Если останется время (27.10 до 14:00): извлечение сведений из выписок трёх шаблонов с F1 по
   сущностям; сверка карточки Авиандра с ГРЛС.
